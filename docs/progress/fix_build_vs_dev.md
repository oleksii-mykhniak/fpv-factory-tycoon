# Фікс «збірка ≠ dev» — 2026-09-11

*Не стадія: один баг з валідації на залізі, який виявився дірою в перевірках.*

## Симптом

Над поштовою скринькою «+$47» з'являвся і **висів вічно**: два продажі — два
написи назавжди. На телефоні й у зібраній грі; у `npm run dev` — все гаразд.

## Причина

Rollup вирізав тіло обробника при tree-shaking. Кожен напис мав власне
замикання над своїм станом:

```js
const st = { lbl, age: 0, live: false, ... }
lbl.on('preupdate', (evt) => {
  if (!st.live) return     // ← rollup згорнув `live: false` у константу
  st.age += frameMs(evt)   // ← і викинув усе, що нижче
  ...
})
```

У бандлі це ставало `lbl.on("preupdate", (evt) => { return })`, а
`FLOAT_GAIN_MS` і `FLOAT_GAIN_RISE` зникали з файлу взагалі. Присвоєння
`st.live = true` у `floatGain()` rollup із тим об'єктом не пов'язав, бо той
дістається через `floaters.find(...)`.

Звели до мінімального прикладу на 15 рядків і прогнали чистим rollup —
відтворюється без vite, без мініфікації, на дефолтних налаштуваннях.

## Інсайти

- **Форма коду вирішує, доживе він до збірки чи ні.** Стан у замиканні над
  об'єктом-літералом із булевим прапорцем — вразливий; той самий стан, узятий з
  масиву в циклі (`for (const st of floaters)`), tree-shaking переживає. Обидва
  варіанти перевірені на зібраному бандлі.
- **Перевірка, яку видно лише очима, — не перевірка.** Анімація «+$47» жила
  п'ять стадій без жодного тесту, бо «її ж видно». Її не було видно нікому:
  ані тестам, ані власнику гри, який дивився на dev.
- **`npm run smoke` ганяв dev-сервер — і тому не міг зловити цей клас у
  принципі.** У dev немає tree-shaking. 1300 рядків smoke показували здорову
  гру, поки в APK анімації не було.
- **Версія в налаштуваннях («0.2.0-dev») не змінювалась від першого дня.** З
  екрана телефона не можна було сказати, чи це сьогоднішня збірка. Для стадій,
  що чекають валідації на залізі, це не косметика, а обов'язковий реквізит.
- APK у `android/app/src/main/assets/` — від 23 червня, тобто старший за
  половину закритих стадій. Усе, що «перевіряється на залізі», перевіряється
  тим, що зібрано, а не тим, що в `main`.

## Що зроблено

- `src/scene/floatGain.js` — чиста `floatPose(age)`: підйом, тон, кінець життя.
  Винесена з обробника кадру, щоб її можна було перевірити тестом.
- `src/scene/scene.js` — один обробник `preupdate` на весь пул написів замість
  обробника на кожен. Висить на першому написі пулу: той доданий через
  `track()`, а отже вмирає разом із розкладкою при перебудові фабрики.
- `src/scene/scene.js` — пружина приймального ящика рахувала кадр як
  `evt.delta ?? 16`; у Excalibur 0.32 `delta` завжди `undefined`, тобто
  анімація йшла «по 16 мс на кадр» незалежно від fps. Тепер `frameMs(evt)`.
- `src/scene/floatGain.test.js` — 5 перевірок пози, включно з «зіпсований вік
  (NaN/undefined) завершує напис, а не робить його вічним».
- `src/scene/bundle.test.js` — збирає гру і дивиться на **байти бандла**: чи
  доїхала формула підйому, чи не приїхав якийсь обробник із порожнім тілом, чи
  читається кадровий час із події. Перевірено, що на старому коді цей тест
  падає — інакше він вартий нуль.
- `npm run smoke:build` (`scripts/smoke-build.mjs`) — той самий smoke, але
  проти `vite build --mode debug` + `vite preview`.
- `vite.config.js` + `settingsModal.js` — у налаштуваннях тепер
  `0.2.0 · <коміт> · <дата збірки>`; `+` після хеша означає незакомічені зміни.
